# AI VTuber Framework Lite

Десктопный MVP для ведения Twitch-стрима виртуальной ведущей. Приложение состоит из Electron/React-панели и локального Fastify-сервера. В обычном запуске история чата и настройки хранятся в `vtuber.sqlite` внутри `app.getPath('userData')`; dev сохраняет прежний путь `data/vtuber.sqlite`. Четыре API/OAuth-ключа хранятся отдельно в зашифрованном `secrets.bin`. Самостоятельные инструменты работы с БД по умолчанию используют `data/vtuber.sqlite`.

2. Полностью распакуйте архив в удобную папку.
3. Откройте вложенную папку `win-unpacked` и запустите **AI VTuber Framework Lite.exe**.

Node.js и npm для готовой сборки не нужны. Python понадобится только при использовании локального Silero. Сохраняйте EXE вместе с остальными файлами папки; запускать его прямо из ZIP не следует.

В релизе также есть `SHA256SUMS.txt` для проверки скачанного архива. Автоматические архивы GitHub **Source code (zip/tar.gz)** содержат исходники, а не готовую программу. Каталог `release/win-unpacked` создаётся при локальной сборке и не хранится в Git.

## Установка из GitHub

Для Windows-разработки используется Node.js 22.x и npm. В репозитории находятся исходники; зависимости, пользовательские данные, ключи и готовые сборки не коммитятся.

```powershell
git clone https://github.com/Alvetore/aivtuberframework.git
Set-Location aivtuberframework
npm ci
npm run build
npm start
```

Готовую папку приложения можно собрать командой `npm run package:dir`; результат появится в `release/win-unpacked`. Команда `npm run package:dist` создаёт Windows-дистрибутивы. Упаковщик пересобирает native SQLite под Electron; для возврата к запуску из исходников может потребоваться `npm rebuild better-sqlite3`. Не копируйте Node-бинарник SQLite в готовый пакет.

## Запуск из исходников в один клик

Самый простой способ — запустить готовый скрипт:
- **Двойной клик по [start.bat](start.bat)** (в Проводнике Windows)
- или в PowerShell: `.\run.ps1`
- или в терминале: `npm start`

Скрипт автоматически проверит зависимости, при необходимости соберет проект и запустит десктопное приложение. **Никаких лишних терминалов держать не нужно**: Electron сам поднимает локальный бэкенд в фоне и чисто гасит его при закрытии окна.

### Режим разработки (Hot-reload)

Если вы редактируете код интерфейса или сервера:
```powershell
npm run dev
```

Electron запускает backend и в dev-режиме. Vite проксирует `/api` и `/ws`; изменения `src/server` и `src/shared` вызывают последовательный перезапуск backend, после которого WebSocket подключается заново. Отдельный backend запускать не нужно.

Для запуска из исходников native-модуль `better-sqlite3` должен соответствовать установленному Node.js (`npm rebuild better-sqlite3`). Упаковщик сам пересобирает его под Electron; после упаковки для возврата к разработке может понадобиться повторный `npm rebuild better-sqlite3`.

### База данных

При запуске `AppDatabase` выполняет транзакционные добавочные миграции, сохраняя существующую историю и настройки. Drizzle Kit используется для разработки схемы; его команды работают с `data/vtuber.sqlite` и не заменяют миграцию профилей при запуске:

```powershell
npm run db:generate   # сгенерировать SQL из src/server/schema.ts
npm run db:migrate    # применить миграции к data/vtuber.sqlite
npm run db:studio     # открыть Drizzle Studio для просмотра БД
```

При работе с БД используются PRAGMA:
- `journal_mode = WAL` — параллельный read/write,
- `busy_timeout = 5000` — ожидание блокировки до 5 секунд,
- `foreign_keys = ON` — каскадное удаление сообщений при удалении зрителя,
- `synchronous = NORMAL` — баланс надёжности и скорости.

### Безопасность

Сервер слушает только `127.0.0.1`. Собранный интерфейс и его API работают с одного HTTP origin на свободном локальном порту. Electron устанавливает случайную сессионную HttpOnly/SameSite=Strict cookie; HTTP, WebSocket и файлы модели требуют эту сессию и проверяют Host/Origin. Порт или URL сами по себе не дают доступа. В dev разрешён origin Vite, запросы идут через его прокси.

Файлы модели доступны только внутри выбранного каталога, с проверкой реального пути и допустимых расширений. Маршрута для произвольных локальных каталогов нет. Electron использует sandbox, `contextIsolation: true` и `nodeIntegration: false`; IPC доступен только основным фреймам доверенных окон.

В «Подключениях» заполните модель и Twitch, затем примените настройки. «Применить и подключить» использует введённые данные. Доступ к списку моделей и успешная генерация отображаются отдельно: наличие ключа означает только «настроено». Twitch считается подключённым после подтверждения входа в канал.

## Рабочая студия

Навигация: «Эфир / Персонаж / Голос / Аватар / Подключения / Диагностика». На экране эфира видны чат, связанные с сообщениями ответы, аватар, текущая операция и очередь речи. Мастер настройки не отправляет запросы автоматически. Локальный тест работает без Twitch, помечается отдельно и не получает контекст живого диалога. Проверки моделей и облачного голоса могут тарифицироваться только после явного нажатия соответствующей кнопки.

- После открытия приложения ведущая **остановлена**. «Начать эфир» требует модель и подтверждённое подключение Twitch; при включённом TTS нужен основной аудиоклиент.
- «Пауза» отменяет генерацию, синтез и речь; чат продолжает поступать. «Продолжить» принимает новые решения, старые задания не возвращаются.
- «Стоп» завершает сессию. «Прервать реплику» оставляет ведущую запущенной. Mute отменяет только звук; текстовые ответы сохраняются. Unmute не воспроизводит отменённый звук.
- Потеря Twitch или аудиоклиента ставит эфир на паузу. После восстановления требуется явное продолжение. Перезапуск backend останавливает ведущую, заменяет состояние новым snapshot и сохраняет черновики интерфейса.
- Тесты голоса и модели доступны при остановке/паузе. Звук пробы может попасть в OBS через захват устройства; это не приватный аппаратный канал.

Формы сохраняют неприменённые изменения в оперативной памяти при переходах между разделами. «Применить» сохраняет, «Отменить изменения» возвращает подтверждённые значения. Внешние обновления не затирают изменённые поля. Закрытие приложения и смена профиля предупреждают о черновиках. Для ключей доступны сохранённое состояние, замена и явное удаление; введённый ключ после сохранения заменяется маской. Черновики ключей не записываются в localStorage.

В «Персонаже» можно создать, переименовать, дублировать и выбрать профиль, экспортировать или импортировать версионный JSON. Профиль содержит характер, поведение, голос и размещение аватара. Подключения LLM/Twitch, четыре ключа и локальный аудиовыход общие. Экспорт исключает ключи, устройства, cookies и путь модели; после импорта модель привязывается вручную. Неверный файл отклоняется целиком. Смена профиля доступна при остановке/паузе; смена на паузе завершает старую сессию, а продолжение создаёт новую. Новые, дублированные и импортированные профили не наследуют чужую историю.

В «Голосе» применяются выбранный системный голос, язык и громкость. Недоступный голос заменяется доступным с уведомлением. Web Speech использует системный аудиовыход Windows; отдельное устройство для него выбрать нельзя. Для синтезированного аудио используется `setSinkId`, когда платформа его поддерживает; при исчезновении выхода показывается предупреждение и выбирается системный выход. Доступ к микрофону автоматически не запрашивается. Lip-sync Web Speech приблизительный.

В «Аватаре» доступны preview, масштаб, сдвиг, подгонка, сброс и беззвучная проверка движения рта. Чистое OBS-окно по умолчанию скрывает управляющую панель; открытие, закрытие и настройка доступны в основном окне. Звук воспроизводит только основное окно; preview/OBS не создают вторую копию речи. Для захвата используйте «Захват окна» в OBS. SVG работает без модели; Live2D использует совместимые Pixi 6 и pixi-live2d-display 0.4.

«Диагностика» содержит поиск/фильтры событий, решения по репликам, историю сессий и фактические задержки, попытки API и provider usage. Пропуски показывают причину и известное время ожидания. Отсутствующие метрики отображаются как «Нет данных»; стоимость не выдумывается. Старые сообщения без привязки к сессии сохранены и доступны первому унаследованному профилю, но не приписываются произвольно архивным сессиям.

### Миграция и восстановление

Перед первым запуском обновлённой версии закройте приложение и сохраните копию всего каталога данных (`vtuber.sqlite` вместе с существующими `-wal`/`-shm`, `secrets.bin`) и старую сборку. В dev это `data`, в обычном приложении — путь `window.appInfo.userData()`. Снимок исходников этого прохода находится в `backups/uiux-source-*`; пользовательские данные и ключи в него не включены.

Обновление добавляет таблицы профилей, метаданных сообщений и операций, а также поля сессий. Оригинальные ID, авторы и тексты не переписываются. Первый профиль наследует старые настройки и явно связан со старым контекстом. Миграция выполняется транзакционно и повторяемо. После аварийного перезапуска незавершённые операции помечаются отменёнными, открытые новые сессии закрываются.

Для полного отката закройте все процессы приложения и восстановите **согласованную копию всего каталога данных и старую сборку**. Дополнительные таблицы не мешают чтению старой версии, но она не понимает изоляцию профилей; не чередуйте запись старой и новой версий в одну рабочую БД. Миграции схемы при запуске выполняет `AppDatabase`; команды Drizzle предназначены для инструментов разработки и не заменяют этот переход.

### Хранение секретов

OAuth Twitch, LLM, OpenAI TTS и ElevenLabs сохраняются main-процессом через `safeStorage.encryptString`. Перед заменой `secrets.bin` временный файл синхронизируется и расшифровывается для проверки. Ошибка шифрования или записи возвращается пользователю; fallback на открытый JSON отключён.

Backend получает активные значения от main-процесса и не сохраняет их в SQLite. API и WebSocket показывают только `***` либо пустую строку; bridge для чтения ключей из renderer удалён. При сохранении поле `***` оставляет ключ прежним, пустая строка удаляет его сразу и после перезапуска. Сохранённое удаление имеет приоритет над старой БД и переменными окружения.

При первом запуске старые ключи из SQLite переносятся в защищённое хранилище. Сначала подтверждается зашифрованная запись, затем удаляются только четыре записи ключей; история, зрители, сессии и прочие настройки сохраняются. При ошибке записи исходные значения остаются в БД, запуск завершается с ошибкой. Повторный запуск безопасно продолжает миграцию. Старый plaintext `secrets.bin` также шифруется перед запуском backend. Для отката на старую версию приложение потребуется закрыть; сохраните актуальный защищённый файл и профиль, поскольку старые версии не поддерживают все четыре ключа в vault. Возвращать их в SQLite автоматически приложение не будет.

В локальном запуске `.env` может задать начальные `TWITCH_OAUTH_TOKEN`, `LLM_API_KEY`, `OPENAI_TTS_API_KEY`, `ELEVENLABS_API_KEY`; существующие сохранённые значения имеют приоритет. Сам `.env` приложение не редактирует.

Путь профиля можно узнать в DevTools: `await window.appInfo.userData()`.

### Проверки

```powershell
npm test
npm run build
node scripts/run-electron-smoke.mjs
node scripts/run-electron-smoke.mjs --dev
node scripts/run-electron-smoke.mjs --packaged
```

Регрессии проверяют доступ к HTTP/WS и файлам, миграцию/очистку ключей, управление собственным процессом Silero, чтение тела LLM с таймаутом, ограничения частоты, lifecycle/отмену, профили, черновики и медиа. Для проверки реального Electron предусмотрен `scripts/electron-smoke.cjs`: он требует отдельный временный профиль `VTUBER_SMOKE_DIR` с именем `vtuber-electron-smoke-*` и последовательные фазы `VTUBER_SMOKE_PHASE=save`, `clear`, `verify`; запускается через `electron scripts/electron-smoke.cjs`. Ключи фиктивные, рабочие `.env` и профиль не используются. Локальный подставной LLM проверяет успешный ответ, отказ, фактические usage и поздний ответ после отмены. Проверяются профили, черновики, clean OBS, 960×640 и масштаб 125–150%. С `--dev` проверяется также горячий перезапуск backend при работающем Vite. Платные API, реальный Twitch и установка Python-зависимостей не используются.

## Реализовано

- Twitch IRC-over-WebSocket connector с обработкой PING/PONG, IRCv3 escape и тегов сообщений;
- SQLite-хранилище зрителей, сообщений, сессий и настроек;
- OpenAI-compatible `chat/completions` клиент с timeout и retry (OpenAI, DeepSeek, OpenRouter, локальные серверы);
- контекст чата, prompt builder с защитой от prompt injection, ограничения cooldown и ответов в минуту;
- TTS-очередь (Web Speech или Silero), lip-sync через AudioContext;
- события ядра, WebSocket обновления интерфейса и журнал;
- React админ-панель со статусами, настройками и тестом входящего сообщения;
- Electron safeStorage для четырёх OAuth/API-ключей;
- автоматический reconnect Twitch IRC с exponential backoff.

## Подключаемые адаптеры

В коде есть интерфейс `AvatarProvider` и адаптер VTube Studio WebSocket. Для внутреннего Live2D включён распространяемый runtime Cubism Core; его лицензия и авторство описаны в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Файлы моделей `.model3.json` и связанные ресурсы предоставляет пользователь. Silero запускается как локальный Python-сервис; скрипт при необходимости устанавливает зависимости и загружает модель. Пользовательские модели и их кэш не входят в Git.

## Важные замечания по эксплуатации

- Локальный сервер по умолчанию слушает только `127.0.0.1`.
- Backend в обоих режимах запускается из Electron main; обычный браузер без сессионной cookie доступа не получает.
- Остановка Silero завершает только процесс приложения. Чужой сервер на занятом порту нужно остановить самостоятельно.
- Не передавайте OAuth/API-ключи в сообщения чата или git.

### Упаковка

Пакет использует обычный каталог `resources/app` (`asar: false`), чтобы отдельный backend видел ESM `package.json` и native-зависимости. Это увеличивает число файлов установки, но исключает отдельные копии окружения для backend и хрупкое разрешение зависимостей из `app.asar.unpacked`.
