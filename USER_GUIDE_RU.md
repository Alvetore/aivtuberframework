## 1. Что делает программа

Программа читает сообщения выбранного канала Twitch, решает, когда ответить, получает текст от языковой модели и при включённой озвучке произносит его выбранным голосом. Встроенный аватар или модель в VTube Studio могут двигать ртом во время речи.

Основная цепочка: **чат Twitch → языковая модель → текст ответа → синтез речи → аудиовыход → захват в OBS**.

У текущей версии есть несколько особенностей:

- Ответы видны в самой программе и могут звучать на стриме. Обратно в текстовый чат Twitch они автоматически не отправляются.
- Программа работает с текстом чата. У неё нет встроенного распознавания вашего микрофона, просмотра игры или анализа картинки стрима. Сведения о происходящем нужно передавать через доступный текстовый контекст.
- Для локального теста модель можно проверить без Twitch и без запуска ведущей.
- Аватар и голос необязательны: можно начать с текстовых ответов.
- «Начать эфир» включает ведущую внутри программы. Запуск трансляции в OBS выполняется отдельно.

## 2. Запуск

### Вариант А. Готовая Windows-сборка — рекомендуется

1. Откройте [GitHub Releases](https://github.com/Alvetore/aivtuberframework/releases).
2. В **Assets** скачайте **AI-VTuber-Framework-Lite-0.1.0-win-x64.zip** для версии 0.1.0. [Прямая ссылка на ZIP](https://github.com/Alvetore/aivtuberframework/releases/download/v0.1.0/AI-VTuber-Framework-Lite-0.1.0-win-x64.zip).
3. Полностью распакуйте архив в удобную папку на компьютере.
4. Откройте вложенную папку **`win-unpacked`** и запустите **AI VTuber Framework Lite.exe**.
5. Дождитесь главного окна и надписи **«Связь установлена»**.

Автоматические файлы GitHub **Source code (zip)** и **Source code (tar.gz)** — это исходники без готового приложения. Для запуска без сборки нужен именно Windows ZIP из Assets. Каталог `release\win-unpacked` появляется при сборке проекта на вашем компьютере; после обычного клонирования Git его нет.

Для этого варианта не требуется отдельно устанавливать Node.js, npm или запускать сервер. Python понадобится только для локального Silero.

Сохраняйте всю папку `win-unpacked`: рядом с EXE находятся необходимые ресурсы. Для удобства создайте ярлык на EXE; перенос одного EXE в другую папку не заменяет перенос приложения.

В Assets опубликован `SHA256SUMS.txt`. При необходимости получите SHA-256 скачанного ZIP командой `Get-FileHash -Algorithm SHA256 .\AI-VTuber-Framework-Lite-0.1.0-win-x64.zip` в PowerShell и сравните значение с этим файлом. До запуска ZIP необходимо распаковать.

### Вариант Б. Запуск из папки проекта

Нужны Node.js и npm. Для разработки в этом проекте проверялся Node.js 22.14.0; разумный исходный вариант — ветка Node.js 22.x. Если получаете проект из GitHub впервые, используйте команды клонирования и установки из [README](README.md#установка-из-github). Пути `C:\11\aivtuberframework` ниже — пример: замените их своим каталогом проекта.

Откройте PowerShell в каталоге проекта:

```powershell
Set-Location C:\11\aivtuberframework
node --version
npm --version
```

Затем дважды щёлкните `start.bat` в папке проекта либо выполните:

```powershell
.\run.ps1
```

Если политика PowerShell запрещает запуск `.ps1`, воспользуйтесь `start.bat`. Менять системную политику для обычного запуска не требуется.

Скрипты устанавливают зависимости, если нет `node_modules`, собирают проект, если нет `dist/server/index.js`, и создают `.env` из примера, если файла ещё нет. Доступ к сети нужен при установке зависимостей. Они не проверяют свежесть уже существующей сборки: после изменения исходников запускайте `npm run build` явно.

Ручной запуск после получения исходников:

```powershell
Set-Location C:\11\aivtuberframework
npm install
npm run build
npm start
```

Если зависимости уже установлены, повторять `npm install` при каждом запуске не нужно. `npm start` запускает существующую сборку; сам по себе он её не обновляет.

### Вариант В. Разработка с обновлением кода

```powershell
Set-Location C:\11\aivtuberframework
npm run dev
```

Этот режим нужен при редактировании программы. Vite обслуживает интерфейс на `127.0.0.1:5173`, Electron запускает backend на `127.0.0.1:3001`. Отдельно поднимать backend не нужно.

При изменении backend он перезапускается, связь восстанавливается, черновики форм остаются. После перезапуска ведущую нужно запустить снова. Dev использует БД в `data/vtuber.sqlite`, но хранилище ключей остаётся в каталоге Electron userData: сам по себе dev не является полностью изолированной песочницей.

## 3. Первое открытие и сохранение настроек

Слева доступны шесть разделов:

| Раздел | Для чего нужен |
|---|---|
| Эфир | Чат, ответы, тест модели, управление ведущей и текущая очередь речи |
| Персонаж | Имя, характер, язык, режим поведения и профили |
| Голос | Синтезатор, голос, громкость, аудиовыход и проба речи |
| Аватар | Встроенный SVG/Live2D, VTube Studio, размещение и OBS-окно |
| Подключения | API языковой модели и Twitch |
| Диагностика | Журнал, решения по сообщениям, ошибки, метрики и сессии |

На «Эфире» можно открыть **«Мастер настройки»**. Он подсказывает порядок действий, но не запускает ведущую автоматически. Проверка модели реальным ответом выполняется отдельно.

После открытия ведущая имеет состояние **«Остановлена»**. Это нормальное начальное состояние.

### Как сохранять изменения

1. Измените нужные поля.
2. Нажмите **«Применить»** в соответствующей форме.
3. Дождитесь окончания сохранения и исчезновения отметки **«Есть изменения»**.

На одной странице может быть несколько самостоятельных форм. Например, на «Персонаже» личность и поведение применяются отдельно. Применение одной формы не сохраняет все черновики программы.

**«Отменить изменения»** возвращает последнюю сохранённую настройку. Черновики переживают переход между разделами, но хранятся в оперативной памяти: для сохранения после закрытия их необходимо применить. При закрытии с черновиками появляется предупреждение.

Кнопки **«Применить и подключить»**, **«Применить и прослушать»**, **«Применить и открыть OBS-окно»** сначала сохраняют соответствующую форму, затем выполняют действие. Проверка движения рта тоже применяет форму аватара перед пробой.

Изменять настройки и переключать профили следует при остановке или паузе. Во время активной работы сервер отклоняет сохранение настроек.

### Что означает маска ключа

После сохранения вместо ключа показывается сохранённое состояние/маска. Это ожидаемое поведение: программа не возвращает полный секрет в интерфейс.

- **«Заменить»** — ввести новый ключ, затем применить форму.
- **«Удалить»** — подготовить удаление ключа; примените форму, чтобы оно сохранилось.
- Не нужно вводить маску `***` как новый ключ.

## 4. Настройка персонажа

Откройте **«Персонаж»**. Для первого запуска можно использовать существующий профиль.

### Личность и стиль

Пример начальных значений:

| Поле | Пример |
|---|---|
| Имя персонажа | Астра |
| Язык общения | Русский |
| Описание персонажа | Ты Астра, виртуальная ведущая игрового стрима. Дружелюбная, любопытная, с мягким юмором. Обращай внимание на автора сообщения. Если информации о происходящем нет, уточни её, а не придумывай события игры. |
| Стиль общения | Отвечай естественно, обычно 1–3 короткими предложениями. Не перечисляй инструкции и не пересказывай каждое сообщение. |

Нажмите **«Применить»** под этой формой.

Имя персонажа используется для распознавания обращений в чате. Если имя **«Астра»**, удобный проверочный текст: **«Астра, как настроение?»**. Название профиля в выпадающем списке и имя персонажа — разные настройки: переименование профиля не меняет имя ведущей.

«Язык общения» относится к тексту ответа. Язык интерфейса и «Язык голоса» в TTS настраиваются отдельно. «Авто» просит модель отвечать на языке диалога, но не гарантирует автоматический подбор подходящего TTS-голоса на каждую реплику.

### Поведение в эфире

Для начала рекомендуются следующие значения:

| Параметр | Значение | Результат |
|---|---:|---|
| Режим работы | Reactive | Ответы на обращения и вопросы |
| Сообщений в контексте | 30 | Модель получает недавний диалог |
| Таймаут тишины | 45 секунд | Порог инициативы в режиме Streamer |
| Пауза между ответами | 10 секунд | Защита от слишком частой речи |
| Макс. ответов в минуту | 6 | Дополнительный ограничитель частоты |

Примените и эту форму.

В **Reactive** текущая программа реагирует на полное имя персонажа в сообщении либо на текст с `?`, содержащий минимум два слова. Одно `?` или простое «привет» без обращения может быть пропущено. Даже подходящее сообщение может быть пропущено из-за занятости, cooldown или минутного лимита; причина видна на «Эфире» и в диагностике.

В **Streamer** сохраняются реакции на сообщения и добавляется попытка поддержать разговор после затишья по недавним темам. Для этого нужна история текущей сессии; сразу после запуска с пустым чатом не следует ожидать монолога. Инициатива подчиняется ограничениям частоты и занятости.

Увеличение контекста повышает объём отправляемого модели текста, задержку и потенциальный расход токенов. Этот контекст не является отдельной долговременной памятью персонажа.

## 5. Подключение языковой модели

Откройте **«Подключения»**, форму модели.

1. Выберите провайдера или введите свой OpenAI-совместимый адрес.
2. Укажите API-ключ этого провайдера.
3. Введите точный идентификатор доступной вам модели.
4. При желании нажмите **«Проверить доступ и получить модели»**.
5. Выберите/уточните модель и нажмите **«Применить»**.

Встроенные пресеты адресов:

| Пресет | Адрес API |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| DeepSeek | `https://api.deepseek.com/v1` |
| Локальный API | `http://127.0.0.1:1234/v1` |

Пресет меняет только адрес. Он не выдаёт ключ и не выбирает подходящую модель автоматически. Модель берите из своего кабинета провайдера или полученного списка; заданное по умолчанию имя не гарантирует доступ в вашем аккаунте.

В поле LLM указывается базовый адрес **без `/chat/completions`**: этот путь программа добавляет сама. Для сервиса с другим протоколом нужен совместимый шлюз; произвольный API генерации текста не обязательно подойдёт.

Проверка списка использует введённые адрес и ключ, даже если форма ещё не применена. Успешный список подтверждает доступ к списку моделей, но не успешную генерацию. Полную проверку делает локальное тестовое сообщение после сохранения.

### Дополнительные параметры

Для старта подходят вариативность `0.7–0.8` и максимальная длина `180–300` токенов. Низкая вариативность обычно даёт более предсказуемые ответы. Слишком маленький лимит может обрывать реплику, большой — делать ответы длинными. Возможности параметров зависят от выбранного API/модели.

### Локальная модель

1. Запустите внешний сервер модели с OpenAI-совместимым API.
2. Загрузите в нём нужную модель и включите HTTP API.
3. Перенесите фактический адрес сервера в приложение. Порт `1234` — лишь пресет, ваш сервер может использовать другой.
4. Укажите точный ID загруженной модели.
5. Текущая программа требует непустое поле ключа для генерации. Если локальный сервер действительно работает без авторизации и игнорирует Bearer-заголовок, можно указать условное значение `local`. Если авторизация включена, нужен настоящий ключ сервера.
6. Примените форму и проверьте ответ на «Эфире».

Программа не загружает и не запускает локальную LLM за вас. Без интернета можно работать только при наличии уже работающей локальной модели и подходящего локального синтезатора.

## 6. Первый тест без Twitch

До настройки стрима полезно проверить цепочку по частям.

1. Оставьте ведущую в состоянии **«Остановлена»**.
2. Для самого первого текстового теста в «Голосе» снимите **«Озвучивать ответы»** и примените форму.
3. Откройте **«Эфир»** и найдите **«Локальный тест»**.
4. Введите, например: **«Привет! Представься в двух предложениях.»**
5. Нажмите **«Проверить ответ»**.
6. Дождитесь текста ответа или конкретной ошибки. Принятие запроса само по себе ещё не означает успех.

Этот тест действительно обращается к выбранной модели и может расходовать платные токены. Он не требует Twitch и не включает ведущую. При включённом TTS ответ также может прозвучать.

Тестовые сообщения отмечаются **«Тест»**, не добавляются в контекст живого разговора и не увеличивают число сообщений активной эфирной сессии. Каждый локальный тест получает отдельный контекст: это проверка ответа, а не полноценный многоходовый локальный чат.

После успешного текста включите голос и повторите проверку. Во время активной работы ведущей тест недоступен — сначала нажмите «Пауза».

## 7. Подключение Twitch

Откройте Twitch в разделе **«Подключения»**.

### Через встроенный вход

1. Нажмите **«Войти через Twitch»**.
2. Самостоятельно выполните вход в открывшемся окне Twitch и подтвердите доступ.
3. После возврата проверьте полученные логин и канал.
4. Нажмите **«Применить и подключить»**.
5. На «Эфире» дождитесь статуса подключённого Twitch.

Встроенный OAuth зависит от внешней страницы авторизации/перенаправления; получение токена этим способом не проверялось с реальным аккаунтом в автоматической приёмке. Если окно не завершает вход, используйте ручной ввод.

### Ручной ввод

| Поле | Что указать |
|---|---|
| Логин Twitch | Логин аккаунта, которому принадлежит OAuth-токен; не отображаемое имя |
| Канал | Имя канала, чат которого нужно читать, без `#` и без полного URL |
| OAuth-токен Twitch | Действующий пользовательский access token для Twitch IRC, в формате `oauth:...` |

Например, для канала `https://www.twitch.tv/my_channel` в поле канала нужно **`my_channel`**. Если используется отдельный бот-аккаунт, логин должен принадлежать боту, а канал — стримеру. Токен должен соответствовать аккаунту из поля логина.

Получайте токен через доверенный OAuth-процесс Twitch с разрешением чтения чата (`chat:read`). При самостоятельной регистрации OAuth-приложения ориентируйтесь на официальную [документацию Twitch по пользовательским токенам](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/). Пароль аккаунта, Client ID и Client Secret не являются заменой access token.

Нажмите **«Применить и подключить»**. Сообщение «запрос подключения принят» означает начало подключения; готовность наступает после подтверждения входа в канал.

Проверка:

1. Напишите сообщение в чате выбранного канала обычным способом.
2. Убедитесь, что оно появилось в «Разговоре» на «Эфире».
3. Если ведущая ещё остановлена, отсутствие ответа ожидаемо.
4. Когда будете готовы, нажмите **«Начать эфир»** и отправьте новое сообщение с именем персонажа, например **«Астра, как настроение?»**.

Ранее пришедшие сообщения после запуска или продолжения не обрабатываются заново автоматически.

## 8. Настройка голоса

Откройте **«Голос»** при остановленной ведущей или на паузе. Включите **«Озвучивать ответы»** и выберите синтезатор.

### Системный голос — самый простой старт

1. Выберите **«Системный голос · бесплатно»**.
2. В «Системном голосе» выберите доступный голос либо **«Автоматически по языку»**.
3. Для русского укажите язык голоса **`ru-RU`**, для английского — например **`en-US`**.
4. Установите громкость, например `70–80%`.
5. Введите текст пробы и нажмите **«Применить и прослушать»**.

Эта проба не вызывает LLM, но применяет настройки формы. Для прерывания есть **«Прервать звук»**.

Если список голосов пуст, установите нужный голос/речевой компонент в параметрах Windows, затем перезапустите программу. Наличие голосов в Windows не гарантирует, что Electron перечислит каждый из них: выбирайте из фактически доступного списка.

Системный синтез использует выход Windows. Выбрать отдельный аудиовыход именно через Web Speech нельзя. Движение рта для него приблизительное. Если ранее выбранный голос исчез, приложение использует доступный вариант и показывает предупреждение.

### Silero — локальный синтез

Для Silero требуется установленный Python, доступный командой **`python`**. Перед настройкой можно проверить в PowerShell:

```powershell
python --version
```

1. Выберите **«Silero · локальный сервер»**.
2. Для первого запуска оставьте `http://127.0.0.1:5000` в дополнительных параметрах.
3. Выберите голос, например `xenia`, и частоту `48000 Гц`.
4. Нажмите **«Применить и запустить»**.
5. Откройте «Диагностику» и дождитесь готовности сервера.
6. Вернитесь в «Голос» и нажмите **«Применить и прослушать»**.

Первый запуск скрипта может автоматически установить отсутствующие `torch` и `numpy` через pip и загрузить модель Silero. Поэтому он требует сети, времени, свободного диска и меняет выбранное Python-окружение. Если зависимости хотите держать отдельно, подготовьте виртуальное окружение заранее и запускайте приложение из терминала с активированным окружением; команда `python` должна указывать на него.

Встроенный скрипт использует русскую модель `v4_ru`. На CPU он работает без видеокарты; GPU используется, если установленный PyTorch видит CUDA. Простое наличие NVIDIA не означает готовый CUDA/PyTorch. Английский текст не делает эту модель английской автоматически.

При долгой первичной установке интерфейс может ещё не подтвердить готовность. Сначала проверьте журнал: не запускайте несколько копий сервера подряд. Если порт занят сторонним процессом, программа его не завершает. Для другого свободного порта измените адрес, предварительно остановив собственный запущенный Silero.

### OpenAI Audio

1. Выберите **OpenAI Audio**.
2. Укажите доступные вам модель синтеза и голос. Встроенные начальные примеры: `tts-1` и `nova`; актуальную доступность проверьте у своего провайдера.
3. Введите отдельный **«Ключ OpenAI Audio»**.
4. При стандартном API оставьте полный URL синтеза `https://api.openai.com/v1/audio/speech`.
5. Нажмите **«Применить и прослушать»**.

У TTS указывается полный URL синтеза, в отличие от базового URL языковой модели. Если отдельный ключ пуст, программа использует сохранённый LLM-ключ. Ключ DeepSeek/OpenRouter/локального сервера обычно не является ключом OpenAI Audio: для такого сочетания задайте отдельный действующий ключ.

Проверка и дальнейшее озвучивание могут тарифицироваться отдельно от генерации текста.

### ElevenLabs

1. Выберите **ElevenLabs**.
2. Введите **«Ключ ElevenLabs»**, **«ID голоса»** и модель.
3. Используйте именно ID доступного вашему аккаунту голоса, а не его отображаемое имя.
4. Нажмите **«Применить и прослушать»**.

Доступность голоса, модели и объём синтеза зависят от аккаунта ElevenLabs. Этот вариант тоже использует внешний сервис и его тариф.

### Выход и громкость

Для Silero и облачного аудио поле **«Аудиовыход»** выбирает устройство, если платформа поддерживает `setSinkId`. Если выбора нет или устройство пропало, используется системный выход и показывается предупреждение. Часть названий устройств может быть скрыта системой; приложение не запрашивает микрофон только ради их списка.

Звук пробы может попасть в OBS через захват соответствующего устройства. Проверяйте его до начала публичной трансляции или при выключенном нужном источнике OBS.

## 9. Настройка аватара

### Встроенный SVG — без файлов модели

1. Откройте **«Аватар»**.
2. В «Способе отображения» выберите **«Аватар в приложении · Live2D или SVG»**.
3. Оставьте поле **«Путь модели»** пустым.
4. Нажмите **«Применить»**.
5. Убедитесь, что виден встроенный SVG-аватар.
6. Нажмите **«Проверить движение рта»**. Проба длится около двух секунд и не воспроизводит звук.

Это удобный вариант проверки всей цепочки до подключения собственной модели.

### Собственная Live2D

1. Выберите тот же внутренний режим аватара.
2. Нажмите **«Выбрать .model3.json или ZIP»**.
3. Укажите файл совместимой Cubism 4-модели или ZIP с её ресурсами.
4. Нажмите **«Применить»** и дождитесь подтверждения загрузки.
5. При необходимости настройте масштаб и сдвиги.

Для прямого файла сохраняйте рядом его ресурсы: `.moc3`, текстуры, физику, движения и другие файлы, на которые ссылается конфигурация. Выбор одного `.model3.json` не копирует недостающие текстуры и не превращает модель другого формата в Live2D. Общий родительский каталог должен содержать нужные ресурсы; доступ за пределы выбранной папки ограничен.

Preview до применения нового пути показывает последнюю применённую модель. **«Подогнать»** возвращает масштаб к `1`; **«Сбросить размещение»** возвращает масштаб `1` и сдвиги `0`. Для сохранения нового размещения примените форму.

Если загрузка модели завершилась ошибкой, проверьте сообщение в основном окне. В некоторых сценариях может отображаться временный SVG; это не подтверждает загрузку вашей Live2D.

### VTube Studio

1. Запустите VTube Studio и загрузите свою модель.
2. В настройках VTube Studio включите доступ к API.
3. В нашей программе выберите **VTube Studio**.
4. Укажите адрес, обычно **`ws://127.0.0.1:8001`**; он должен совпадать с портом VTube Studio.
5. Нажмите **«Применить и подключить»**.
6. В окне VTube Studio самостоятельно разрешите запрос плагина **AI VTuber Framework Lite**.
7. Дождитесь подтверждения подключения и проверьте движение рта.

Для lip-sync используется параметр `MouthOpen`; модель и настройки VTube Studio должны корректно реагировать на него. В этом режиме захватывайте в OBS саму VTube Studio. Встроенное OBS-окно нашей программы предназначено для внутреннего SVG/Live2D, а не для переноса картинки из VTube Studio.

## 10. Подключение OBS

### Изображение внутреннего аватара

1. В нашей программе выберите внутренний аватар и проверьте его preview.
2. Включите **«Чистое окно для OBS»**.
3. Выберите фон.
4. Нажмите **«Применить и открыть OBS-окно»**.
5. В OBS добавьте источник **«Захват окна»**.
6. Выберите **AI VTuber Avatar Overlay**, а не главное окно студии.
7. Настройте размер и положение источника на сцене.

Попробуйте прозрачный фон. Если конкретный режим захвата Windows/OBS не сохраняет прозрачность, выберите в программе зелёный, синий или пурпурный хромакей, примените форму и добавьте фильтр **«Хромакей»** к источнику OBS. Выбирайте цвет, которого нет на модели.

Чистый режим скрывает кнопки внутри окна аватара. Закрыть его можно из основной программы кнопкой **«Закрыть OBS-окно»**. Сохранение изображения при минимизации зависит от режима захвата: проверьте поведение сцены заранее, при необходимости оставьте окно открытым.

### Звук

Речь воспроизводит **главное окно программы**. OBS-окно и preview не создают ещё одну копию звука.

Для первого запуска проще захватывать устройство Windows, в которое звучит ведущая:

1. В OBS включите нужный **«Звук рабочего стола»** либо добавьте **«Захват выходного аудиопотока»** с этим устройством.
2. В программе запустите пробу голоса.
3. Убедитесь, что индикатор в микшере OBS двигается и уровень не уходит в красную зону.
4. Сделайте короткую локальную запись и прослушайте её.

Для раздельного захвата можно использовать доступный в вашей версии OBS **«Захват аудио приложения»**, выбрав процесс основного приложения, либо отдельный аудиовыход/виртуальное устройство. Поддержку конкретного варианта проверьте записью. Web Speech использует системный выход, поэтому для него удобнее начинать с захвата соответствующего устройства.

Не захватывайте один и тот же голос двумя источниками одновременно: например, через общий звук рабочего стола и отдельный захват того же приложения. Это даёт удвоение/эхо. Также проверьте аудиомониторинг OBS, если слышите петлю.

Само изображение аватара в OBS не означает, что звук тоже захватывается. Проверяйте их отдельно. Не выводите на стрим страницу настроек с вводимыми ключами.

## 11. Управление эфиром

Сначала настройте и проверьте модель, затем голос/аватар, подключите Twitch. На «Эфире» нажмите **«Начать эфир»**.

Для запуска нужны сохранённые ключ и имя модели, подтверждённое подключение Twitch и, при включённом TTS, основной аудиоплеер. Предварительная успешная генерация помогает проверить настройки, но само наличие ключа ещё не доказывает их правильность.

| Кнопка | Что происходит |
|---|---|
| Начать эфир | Ведущая начинает обрабатывать новые сообщения, создаётся сессия |
| Пауза | Генерация, синтез и текущая речь отменяются; Twitch-чат продолжает поступать |
| Продолжить | Ведущая принимает новые сообщения; старые отменённые задания не возвращаются |
| Стоп | Ведущая останавливается, текущая сессия завершается |
| Прервать реплику | Отменяется текущая реплика и звук; ведущая остаётся в текущем режиме работы |
| Выключить звук | Речь отменяется, но генерация текстовых ответов остаётся активной |
| Включить звук | Озвучивание разрешено для новых реплик; старые отменённые не проигрываются |

Если Twitch или основной аудиоклиент потеряны во время работы, эфир ставится на паузу с причиной. После восстановления соединения нажмите **«Продолжить»** самостоятельно. После перезапуска backend состояние начинается с остановки.

Для изменения характера, API, голоса или профиля сначала используйте «Паузу», примените настройки, затем продолжите. «Выключить звук» не останавливает запросы к LLM и их возможную тарификацию — для этого используйте паузу или стоп.

## 12. Профили и перенос настроек

Управление находится в верхней части **«Персонажа»**.

- Чтобы создать профиль, раскройте **«Создать, переименовать, перенести профиль»**, введите имя и нажмите **«Создать»**. Затем выберите его в списке и нажмите **«Выбрать»**.
- Для переименования выберите нужный профиль в списке, введите новое название и нажмите **«Переименовать»**.
- **«Дублировать»** создаёт копию настроек без чужой истории и сессий. Выберите копию явно; локальную модель понадобится привязать заново.
- **«Экспорт JSON»** сохраняет выбранный профиль в файл.
- **«Импорт JSON»** создаёт профиль из совместимого файла. После импорта выберите его явно и при необходимости заново укажите модель.

Профиль содержит личность, язык, поведение, выбор голоса и оформление аватара. Общими остаются подключения и адреса сервисов, ключи и локальный аудиовыход. Выбор LLM тоже общий: переключение персонажа само по себе не переключает провайдера/модель.

Локальная привязка Live2D не переносится через экспорт и не копируется дублированием. JSON не содержит ключей, подключений, устройств или истории, поэтому **экспорт профиля не является резервной копией приложения**.

Импортируется только поддерживаемый формат; максимальный размер файла — 1 МБ. Не добавляйте в JSON ключи API вручную: лишние/неподдерживаемые поля отклоняются.

Переключение профиля доступно при паузе или остановке. Если есть неприменённые черновики, программа предложит их отменить. При переключении на паузе предыдущая сессия закрывается; новая появится только после продолжения. Новые профили не наследуют чужую историю.

## 13. Диагностика и типичные проблемы

В «Диагностике» ищите ошибку по времени, источнику или тексту, фильтруйте журнал и открывайте историю сессий. На «Эфире» можно нажать статус операции возле сообщения и посмотреть подробности: причину пропуска, задержку модели/голоса, попытки API и доступные токены.

**«Нет данных»** означает, что метрика неизвестна или не была передана провайдером, а не нулевой расход. Точную стоимость смотрите в кабинете провайдера. Лимит ответов в минуту ограничивает частоту, но не является денежным бюджетом.

| Симптом | Что проверить |
|---|---|
| «Начать эфир» недоступно | Причину под кнопками; сохранены ли ключ/модель, подключён ли Twitch, восстановлена ли связь основного окна |
| Настройки не применяются | Пауза/остановка, ошибки полей, отдельная кнопка «Применить» именно этой формы; дождитесь предыдущего сохранения |
| Сообщения видны, ответов нет | Ведущая запущена? Есть имя персонажа или вопрос? Не действует ли cooldown/минутный лимит? Не занята ли генерация? |
| Тест отвечает, реальный чат молчит | Локальный тест обходит фильтр обращений и ограничения частоты; проверьте live-состояние и причину операции реального сообщения |
| Ответ появился только в программе | Это ожидаемо: автоматической отправки ответа обратно в чат Twitch нет |
| API возвращает 401/403 | Правильность ключа, доступ аккаунта к модели/API, отсутствие ключа от другого провайдера |
| API возвращает 404 | Базовый адрес без повторного `/chat/completions`, точный ID модели и совместимость API |
| API возвращает 429 | Лимит/баланс провайдера; снизьте частоту и проверьте кабинет |
| Список моделей получен, генерация ошибочная | Доступ к списку не гарантирует доступ к выбранной модели или поддержку параметров запроса |
| Ответ обрывается | Увеличьте допустимую длину ответа; проверьте ограничения модели |
| Есть текст, звука нет | «Озвучивать ответы», mute, громкость, доступность голоса, аудиовыход, основной плеер и результат отдельной пробы |
| Голос слышен, но отсутствует в OBS | Устройство/источник захвата OBS; OBS-окно само звук не воспроизводит |
| Голос слышен дважды | Два источника одного аудиосигнала или мониторинг OBS |
| Нет системных голосов | Речевые компоненты Windows и фактически доступный приложению список; после установки перезапустите программу |
| Silero не стартует | Команда `python`, pip/зависимости, загрузка модели, журнал, свободный порт и корректный localhost-адрес |
| Twitch не подключается | Соответствие логина токену, срок/права токена, имя канала без URL, доступ сети; дождитесь подтверждения JOIN |
| После reconnect ведущая молчит | Нажмите «Продолжить», а после перезапуска backend — «Начать эфир» |
| Аватар обрезан/уехал | «Сбросить размещение», затем «Применить»; проверьте размер окна и размещение источника в OBS |
| Вместо Live2D SVG или ошибка | Применён ли новый путь, присутствуют ли ресурсы модели, совместимость Cubism и текст ошибки |
| VTube Studio не подключается | Внешнее приложение запущено, API включён, порт совпадает, запрос плагина разрешён |
| Открытие локального URL в другом браузере не работает | Используйте настольное приложение: доступ защищён сессионной cookie Electron |

При ошибке `NODE_MODULE_VERSION`/`better-sqlite3` в запуске из исходников проверьте Node.js и соответствие native-модуля. Закройте приложение и выполните в каталоге проекта:

```powershell
npm rebuild better-sqlite3
npm run build
npm start
```

Это восстанавливает зависимость для Node, который запускает backend из исходников. Готовая Electron-сборка содержит свою версию модуля; не подменяйте её бинарником из `node_modules` проекта.

Если нужно передать проблему разработчику, сохраните текст ошибки, название раздела, действие перед ошибкой, тип запуска и провайдера/модель. Перед передачей проверьте, что материалы не содержат ключей, токенов или приватного чата.

## 14. Данные, резервная копия и обновление

В обычном запуске настройки и история находятся в `vtuber.sqlite` в каталоге пользовательских данных Electron. На стандартной Windows для этого package name обычно это `%APPDATA%\ai-vtuber-framework-lite`; при нестандартном запуске путь может отличаться.

Точный путь можно получить в DevTools главного окна через консоль:

```javascript
await window.appInfo.userData()
```

Для открытия DevTools в стандартном Electron обычно используется `Ctrl+Shift+I` или меню View. Выполняйте только указанное чтение пути; редактировать БД через консоль для настройки программы не нужно.

Ключи хранятся отдельно в **`secrets.bin`**, зашифрованном средствами Electron/Windows. В dev БД находится в `C:\11\aivtuberframework\data\vtuber.sqlite`, а ключи — по-прежнему в Electron userData. Для полной резервной копии dev учитывайте оба каталога.

### Перед обновлением

1. Нажмите **«Стоп»** и закройте приложение.
2. Убедитесь, что его процессы завершились.
3. Скопируйте **весь каталог пользовательских данных** в отдельную папку. Если присутствуют `vtuber.sqlite-wal` и `vtuber.sqlite-shm`, сохраняйте их вместе с БД; не копируйте только основной файл при работающем приложении.
4. Для dev дополнительно сохраните каталог `data`.
5. Если модель выбрана из внешней папки, сохраните и эту папку.
6. Сохраните старую папку сборки.
7. Замените папку приложения новой сборкой и запустите её.

Миграция выполняется автоматически. Первый унаследованный профиль сохраняет старые настройки/контекст; старые записи не приписываются случайным новым профилям. В старых сессиях могут отсутствовать связи с сообщениями — это объясняется в диагностике.

Для отката восстановите согласованную резервную копию данных и старую сборку при закрытых процессах. Не чередуйте запись старой и новой версий в одну БД.

Защищённый файл ключей не следует считать переносимым между другими Windows-пользователями/компьютерами: для переноса персонажа используйте JSON, а секреты на новом месте введите заново. Секреты не стоит хранить в обычном экспортируемом профиле.

## 15. Короткий порядок действий перед стримом

1. Запустить готовый EXE и дождаться **«Связь установлена»**.
2. Выбрать персонажа и проверить сохранённые имя/режим поведения.
3. Проверить модель локальным сообщением на «Эфире».
4. В «Голосе» прослушать пробу и проверить громкость/выход.
5. Проверить аватар и открыть его OBS-окно либо подключить VTube Studio.
6. Сделать короткую запись в OBS: проверить изображение, звук и отсутствие эха.
7. В «Подключениях» подключить Twitch и дождаться подтверждения.
8. В нашей программе нажать **«Начать эфир»**.
9. Написать в Twitch новое обращение к персонажу и дождаться ответа.
10. Когда всё работает, запустить публичную трансляцию в OBS.

По окончании нажмите **«Стоп»** в программе, завершите трансляцию в OBS и закройте приложение. Настройки сохраняются после применения; запуск ведущей при следующем открытии выполняется явно.
